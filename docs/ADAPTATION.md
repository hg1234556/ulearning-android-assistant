# 雷电与优学院页面适配

适配的目标是把 App 当前界面上的真实控件映射为操作。普通课程操作仍使用默认示例选择器；“求是读书”的 PDF 阅读器使用独立的视觉校准，二者需要分别验证。

## 已验证的求是读书布局（2026-10-19）

- 环境：雷电模拟器、Android 14、优学院 1.9.85，设备截图尺寸 1920 × 1080。
- 文档：《资本论》，共 376 页。已实际验证 `1 / 376 → 2 / 376 → 1 / 376`。
- Android UI 层级只返回 WebView，未提供可读的 PDF 正文或翻页控件。
- 独立阅读器使用 Windows 本地 OCR 确认顶部书名和 PDF 工具栏页码，然后点击工具栏内部已校准的上一页或下一页位置。
- 每次翻页前重新核对上次识别状态，单次只发送一次点击；点击后必须确认同一本书页码恰好改变 1。识别失败、尺寸变化或前台离开优学院时停止，不重试不确定的点击。
- 未验证：全书连续翻页、其他分辨率和阅读器布局、PDF 正文完整导出、平台阅读学时或任务完成。

中文界面使用独立“求是读书”标签，先识别，再单步翻页。底部“下一页”可能切换书籍，不能用来做 PDF 文档翻页。阅读器默认校准内置于 `ReaderConfig`，不随普通 `--profile` 选择器变化；1920 × 1080 以外的截图会被拒绝，重新适配前不要缩放坐标强行点击。

视觉识别需要 Windows 10+、Windows PowerShell 5.1 和系统已安装的可用 OCR 语言。脚本位于包内 `ulearning_assistant/assets/ocr-image.ps1`，所有截图识别均在本机完成。本地演示不支持这条路径。

定时运行默认 300 秒、间隔 30 秒、最多翻页 10 次；次数设为 0 时只做本地计时。运行使用同一后台任务锁，停止按钮和关闭窗口都会请求取消。日志中的 `elapsed_seconds` 仅累计成功识别同书状态之间的本机时间，`platform_confirmed` 固定为 `false`。日志不能证明优学院已累计阅读学时。

### 走神暂停恢复

GUI 的“自动处理走神暂停”默认启用，定时运行最多恢复 10 次，可修改上限或取消勾选。单独处理当前弹窗使用“处理当前走神弹窗”按钮或 `reader resume`，不要求之前已有页码识别结果。`reader status` 与“识别阅读器”保持只读，识别到暂停会报告 `platform_paused`，不会自行点击。

恢复流程先识别真实走神提示和唯一“继续学习”按钮，最多发送一次点击，然后确认弹窗消失并核对同一本书。目标不唯一、恢复未确认、书名改变或次数上限用完时停止。通用页面采集没有自动处理此弹窗的能力，必须使用独立读书流程。

暂停出现后停止累计本地阅读时间，恢复成功后重新开始确认计时；暂停停留时间另记为 `paused_seconds`，成功恢复次数另记为 `resume_count`。运行开始前会用最近识别的状态核对当前文档，避免打开另一篇后沿用旧状态。恢复日志依然不代表平台学时确认。

CLI 可用 `reader run --no-auto-resume` 关闭自动恢复，或用 `--max-resumes 5` 修改上限。真实恢复次数、弹窗布局和长时运行结果应按实际测试补记，不能由模拟测试推断平台效果。

## 1. 建立设备连接

启动雷电并打开优学院，启用雷电的 ADB 本地调试。先执行：

```powershell
python -m ulearning_assistant devices
python -m ulearning_assistant doctor
```

如果自动发现失败，指定雷电目录下的 ADB。路径示例：

```powershell
python -m ulearning_assistant --adb "C:\leidian\LDPlayer14\adb.exe" devices
```

只有状态为 `device` 的目标才能继续读取。多台设备同时在线时，始终用 `--serial` 指定序列号，避免点到其他设备。模拟器未启动、ADB 版本冲突或调试选项未开启，都可能导致连接失败，应以诊断输出为准。

## 2. 读取真实页面

手动进入目标课程，使用桌面界面的页面读取和截图功能，或者执行：

```powershell
python -m ulearning_assistant --serial emulator-5554 inspect
python -m ulearning_assistant --serial emulator-5554 export --output exports/adaptation
```

核对控件文字、资源 ID、内容描述和位置是否与屏幕一致。普通 Android 控件较容易读取；画布、视频、图片或部分 WebView 里的文字可能不会出现在 UI 层级中。导出缺少正文时，不能据此推断平台没有该内容。Windows OCR 当前仅用于独立阅读器的书名和页码校验，普通文字导出仍按 UI 控件内容生成。

## 3. 配置精确选择器

复制默认配置到 `local/` 后修改，并通过 `--profile` 指定副本：

```powershell
python -m ulearning_assistant --profile local/my-course.json gui
```

默认配置包含这些操作名：

| 操作名 | 用途 | 适配要求 |
| --- | --- | --- |
| `next_page` | 下一页 | 在当前课件页读取真实按钮 |
| `play` | 播放 | 确认是播放器按钮，而非课程列表项 |
| `speed_menu` | 打开倍速菜单 | 先确认 App 提供该入口 |
| `speed_1_5` | 选择 1.5 倍 | 打开菜单后重新读取页面并匹配真实选项 |
| `speed_2` | 选择 2 倍 | 同上；没有该选项时不能通过此配置生成该能力 |

选择器支持精确的 `text`、`resource_id`、`description`。使用真实读取到的完整值；不按子字符串模糊匹配，也不要把猜测的按钮名称当作已适配结果。选择器同时指定多个字段时，应按程序显示的匹配结果确认目标。

修改后，先进行操作预览，检查匹配数量与目标位置，再执行点击。如果没有匹配，重新读取当前页；如果出现多个匹配，应增加选择条件。页面变化后不要继续使用旧的预览结果。

## 4. 验证单步，再验证连续采集

1. 先保存当前页面内容。
2. 预览并执行一次“下一页”，人工核对是否进入预期页面。
3. 重新读取页面，确认文字发生了预期变化。
4. 设置较小的最大页数和有限超时，试运行连续翻页采集。
5. 试用取消功能，确认可以终止后续操作。

相同页面重复出现、按钮消失、弹窗覆盖或控件识别失败，都需要停止并检查。页数限制代表最多尝试采集的范围，不等于平台已确认课件完成；文字导出和点击日志也不能证明学时已被认可。

## 5. 记录验证范围

建议在本地记录雷电版本、Android 版本、优学院版本、站点、课件类型、实际选择器与验证日期，避免把某个页面的结果推广到所有课程。记录应注明：

- 哪个设备已成功连接，哪些页面能读取正文。
- 下一页、播放和各倍速按钮是否逐项验证。
- 连续采集的页数、停止原因与取消效果。
- 哪些结果来自演示数据或自动化测试，哪些来自真实设备。

真实截图、控件导出和个人信息保留在 `exports/` 或 `local/`。本仓库只提交代码、文档和不含个人数据的通用配置。
